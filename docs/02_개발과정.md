# 02. 개발 과정

iq-test를 마친 뒤 같은 방식(방향 결정 → 집중 조사 → 세부 질의응답 → 단계별 구현)으로 만들었습니다.

## 1. 방향 결정

사용자에게 "딥리서치로 먼저 다 모을지, 차근차근 정할지"를 묻자 추천 방식(방향 먼저)을 택했습니다.
EQ는 능력형/자기보고형 갈림길이 커서, 방향을 정하지 않고 모으면 두 방향 자료가 섞이기 때문입니다.

| 질문 | 결정 |
|---|---|
| 측정 방식 | 능력형 + 자기보고 섞기 (점수는 능력형, 자기보고는 비교용) |
| 영역 | 감정 인식·이해·조절·대인관계·공감 + **위기 대처·맥락 파악**(사용자 추가) → 보고서 검토 후 **감정 활용** 추가, 7개 |
| 기술 구조 | iq-test와 동일 (Streamlit + SQLite/Supabase, 익명, 관리자 페이지) |
| 차수 | iq-test처럼 1·2·3차 검증 + 심층검사 |
| 감정 인식 형식 | AI 생성 얼굴 이미지 절반 + 글 절반 (이미지는 사용자가 생성) |
| 자기보고 | 1차 전 한 번, 영역당 4문항 + 점검 4문항 |
| 점수 | EQ (감성지수), 평균 100·표준편차 15 (조사 결과 EQ-i·MSCEIT 방식) |
| 위기 대처 | 문항마다 짧은 제한시간 |
| 응답 형식 | 4지선다 + 어려운 단계는 최선·최악 함께 고르기 |
| 응시자 정보 | 받지 않음 (완전 익명) |
| 문항 작성 | Claude 초안 → 사용자 검토 |

## 2. iq-test 틀을 EQ에 맞춘 것

| 장치 | iq-test | eq-test |
|---|---|---|
| 슬롯 | 영역-유형-난이도 | 같음, 영역마다 4유형 × 4난이도 = 16슬롯 |
| 구성 | 정밀 8 · 빠른 4 | 같음 × 7영역 = 56 / 28문항 |
| 동형 문항 | 슬롯당 6 (생성기) | 직접 쓰므로 최소량 계산: 고정 슬롯 3 + 나머지 2 = **영역당 40** |
| 찍기 확률 | 0.2 | 4지선다 0.2 · 최선·최악 **1/12** |
| 새로 생긴 것 | — | 자기평가, 이미지 대체 출제, 문항별 초시계, 다수 응답-정답 비교 |

## 3. 단계별 구현

| 단계 | 내용 |
|---|---|
| 1 | 뼈대, DB, 문항 스키마(7영역·112슬롯), 검증 스크립트, 예시 문항 6개 |
| 2 | 문항 267개(이미지 대기 감정 인식 제외 영역당 40) + 자기평가 32개, 검토 화면 |
| 3 | 검사 화면: 자기평가 → 영역 안내 → 문항(4지선다 / 최선·최악), 위기 대처 문항별 초시계, 새로고침 복원 |
| 4 | 채점·결과: EQ·90% 범위·상위 %, 차수별 탭, 영역 프로필, 강점·약점, 자기평가 비교, 키우는 방법, 결과 카드 |
| 5 | 관리자 분석: 문항 판정, 다수 응답-정답 불일치, 신뢰도, 자기평가 α, 차수·심층검사, 문항은행 현황, 보정값 |
| 6 | 봇 시뮬레이션(분석 확인용), 시뮬레이션 규준(모드별 2만 명), DB 점검 스크립트, 배포 문서 |

## 4. 만들면서 찾아 고친 것

| 찾은 경로 | 문제 | 수정 |
|---|---|---|
| 검증 스크립트 | 4개 영역에서 빠른 구성이 정밀 구성 밖의 슬롯을 씀 | 빠른 구성을 정밀 구성의 부분집합으로 |
| 테스트 | 이미지 대체 문항이 같은 검사지의 다른 문항과 겹칠 수 있음 | 문항 있는 슬롯을 먼저 채우고 대체는 나중에 |
| 검사지 1,800개 점검 | 정밀 3차 감정 인식에서 2%가 앞 차수 문항 재사용 | 대체 문항을 남은 문항이 가장 많은 슬롯에서 가져오게 (6,000개 점검 0건) |
| 문항 작성 | 위기 대처 평균 132자인데 20초 제한 | 25초(쉬움·보통)·35초(어려움 이상)로 |
| 브라우저 | 최선·최악 버튼이 "가장 효과적"이라 해석 문항과 맞지 않음 | 모든 영역 공통 "✓ 가장 맞음 / ✗ 가장 아님" |
| 점검 | '가장 덜 효과적' 보기가 A 자리에 몰림 (20개 중 7개) | 최악 보기 위치도 슬롯마다 순환 |
| 문항 작성 | 문장 끝에 공백이 빠진 문항 2개 | 생성 스크립트 수정 |
