# 04. 운영자 가이드

## 1. 관리자 페이지

- 상단 메뉴 **관리 → 분석**. 비밀번호는 Secrets의 `admin_password`.
- 맨 위 **저장소** 표시를 먼저 확인합니다. 배포 환경에서 `SQLite`면 재시작 때 데이터가 사라집니다 ([DEPLOY.md](../DEPLOY.md)).
- **시뮬레이션 데이터 포함**을 켜면 `scripts/simulate.py`로 만든 가상 응시도 함께 봅니다.

| 탭 | 보는 것 |
|---|---|
| 개요·점수 분포 | 시작·완료, 규준에 쓰이는 첫 응시 수, 소요 시간, 탭 이탈, EQ 분포 |
| 문항 분석 | 문항별 정답률·예측 정답률·변별도·판정, 보기 선택 분포 |
| 신뢰도 | 영역별 주변 신뢰도, 1·2차 동형 검사 신뢰도 |
| 자기평가 | 영역별 α·평균·표준편차, 응답 점검 문항, **응답 신뢰도 분포·목록**, 자기평가↔EQ 상관 |
| 차수·심층검사 | 어디까지 이어 했는지, 심층검사 영역별 문항 수·최종 오차 |
| 문항은행 | 영역별 문항 수와 슬롯 채움 비율, 형식 오류 |
| 내보내기 | 응답·세션 CSV, 문항 모수 보정값 JSON |

## 2. 문항 판정 (응답 30개 이상)

| 판정 | 기준 | 조치 |
|---|---|---|
| 너무 쉬움 / 너무 어려움 | 정답률 > 90% / < 10% | 보기 난이도 조정 또는 교체 |
| 변별도 낮음 | 정답 여부와 능력의 상관 < 0.2 | 정답이 애매하거나 찍기로 풀리는지 점검 |
| 예상보다 쉬움 / 어려움 | 실제 − 예측 정답률 차이 > 0.15이고 \|z\| > 3 | 보정값 적용 |
| **다수 응답과 정답 불일치** | 능력 상위 절반이 정답이 아닌 보기를 가장 많이 고름 (10%p 이상 차이) | **정답 근거와 보기 표현을 다시 검토.** 보기 선택 분포에서 어떤 보기로 몰렸는지 확인 |

EQ 문항은 정답이 이론으로 정해져 있어, '다수 응답과 정답 불일치'가 가장 중요한 신호입니다.
잘하는 사람들이 일관되게 다른 답을 고른다면 정답이 틀렸거나, 두 보기가 모두 맞게 읽히는 문항일 가능성이 큽니다.

## 3. 문항 고치기

1. 문항 ID 확인 (예: `reg-impulse-3b`)
2. `scripts/items_<영역>.py`에서 문항을 고치고 (감정 이해는 `items/und.json` 직접) `python scripts/items_<영역>.py`로 JSON을 다시 만든다
3. 이미 응답이 쌓인 문항의 정답·보기를 바꿨다면 **`version`을 1 올린다** (응답 기록과 구분)
4. 검증·테스트 후 커밋
   ```bash
   python scripts/validate_items.py --strict
   python -m pytest -q
   python scripts/render_review.py      # review/items_review.html로 눈으로 확인
   ```

## 4. 보정값과 규준

- 관리자 → 내보내기 → **보정값 JSON**을 `items/calibration.json`으로 저장해 커밋하면 채점이 실제 난이도를 씁니다.
- 문항 난이도나 구성을 바꾸면 **봇 시뮬레이션 규준을 다시 만듭니다** (약 10분):
  ```bash
  python scripts/build_sim_norms.py --n 20000 --workers 8
  python scripts/plot_norm_curves.py     # 문서 그래프 (matplotlib 필요)
  ```
- 같은 모드의 1차 첫 응시가 100명을 넘으면 결과 화면의 기준이 실제 분포로 자동으로 바뀝니다.
- **자기평가 가정 분포**(평균 3.6, 표준편차 0.55, `core/report.py`의 `SELF_NORM`)는 자기평가 탭의 '전체' 평균·표준편차가 충분히 쌓이면 그 값으로 바꿉니다.

- **응답 신뢰도**: 봇 검증에서 성실한 응답자의 '낮음'은 약 2%였습니다. 실제 '낮음'이 이보다 훨씬 많으면 마지막 질문 문구가 헷갈리거나 기준이 엄격하다는 뜻이니 `core/validity.py` 기준값을 보고 `scripts/simulate_validity.py`로 다시 검증합니다 ([10](10_응답_신뢰도_검증.md)).

## 5. 이미지 문항 추가

[08. 이미지 문항 제작](08_이미지_문항_제작.md)의 프롬프트로 이미지를 만들어 `assets/images/`에 넣고 문항을 추가합니다.
이미지가 없는 동안에는 같은 난이도의 글 문항이 대신 출제되며, 관리자 → 문항은행 탭에 빈 슬롯으로 표시됩니다.

## 6. 시뮬레이션 데이터 (로컬 전용)

```bash
python scripts/simulate.py --n 600     # 가상 응시자 (기본 로컬 SQLite)
python scripts/simulate.py --reset     # 시뮬레이션 데이터만 삭제
```

- 문항 12개는 참 난이도를 크게 틀고, 6개는 '정답 키 오류'(잘하는 사람이 다른 보기를 고름)를 흉내 냅니다. 관리자 분석이 이를 잡는지 확인할 수 있습니다.
- `app_version="sim"`으로 저장되어 규준에 들어가지 않습니다. **배포 DB에는 넣지 마세요.**

## 7. 배포·장애

배포 절차는 [DEPLOY.md](../DEPLOY.md). Streamlit Cloud에서 푸시 직후 `ImportError`가 나면 코드 문제가 아니라 부분 재로딩 문제라 **Manage app → ⋮ → Reboot app**으로 해결합니다 (iq-test에서 확인).
