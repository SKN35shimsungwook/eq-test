# 05. 개발자 가이드

## 1. 실행

```bash
pip install -r requirements-dev.txt
streamlit run streamlit_app.py
python -m pytest -q
python scripts/validate_items.py [--strict]
python scripts/render_review.py [영역 코드…]      # review/items_review.html
python scripts/simulate.py --n 600                 # 로컬 가상 응시
python scripts/build_sim_norms.py --n 20000 --workers 8
python scripts/simulate_styles.py --n 30000 --workers 8   # 유형 판정 검증
python scripts/simulate_validity.py --n 21000 --workers 8 # 응답 신뢰도 검증
python scripts/check_db.py "postgresql+psycopg2://..."
```

## 3. 핵심 개념

### 슬롯과 구성표
- 슬롯 ID `영역-유형-난이도` (예 `reg-impulse-3`), 문항 ID는 슬롯 + 동형 글자 (`reg-impulse-3b`).
- 영역마다 유형 4개 × 난이도 4 = 16슬롯, 관계 갈등만 유형 5개 = 20슬롯 → 8영역 132슬롯.
- 정밀 구성 8슬롯(난이도 1·2·2·2·3·3·3·4, 같은 유형 최대 2번), 빠른 구성 4슬롯(정밀 구성의 부분집합, 난이도 1~4 하나씩).
- 동형 수: 고정 구성 슬롯 3개(1·2·3차), 나머지 2개(심층검사) → 영역당 40, 관계 갈등 48 (`DomainSpec.min_pool`).
- `validate_blueprint()`가 이 규칙을 모두 검사합니다.

### 문항 형식
| 형식 | 난이도 | answer | 응답 문자열 | 찍기 확률 c |
|---|---|---|---|---|
| `mcq` | 1·2 | 보기 인덱스 | `"2"` | 0.2 |
| `best_worst` | 3·4 | `[최선, 최악]` | `"1,3"` (한쪽만 고르면 `"1,"`) | 단계별 1/4 · 1/3 |

- **부분 점수**: `score_item`은 최선·최악에서 최선만 맞으면 `(False, 0.5)`. 채점(`scoring.category_probs`)은 두 단계 순차 모형 (① 최선 맞히기 P1, ② 최선을 맞혔을 때 최악 맞히기 P2, θ=0에서 P1 = P2 = √expected_p). 추정은 행의 `score`(1·0.5·0)를 쓰고 `correct`(둘 다 맞음)는 '맞힌 문항'·문항 판정에만 씁니다.

- 형식·예상 정답률·위기 대처 제한시간은 슬롯에서 자동으로 채워집니다 (`Item.from_dict`).
- 로드할 때 슬롯마다 최선 보기는 A~D를 돌아가며, 최악 보기도 나머지 자리를 돌아가며 놓입니다.

### 이미지 대체 출제
`build_form`은 문항이 있는 슬롯을 먼저 채우고, 빈 슬롯(이미지 대기)은 같은 영역·난이도의 글 유형에서 대신 고릅니다.
고정 구성 밖 슬롯을 먼저 쓰고, 그다음 **남은 문항이 가장 많은 슬롯**에서 가져와 뒤 차수에서 문항이 모자라지 않게 합니다.
`validate_bank(strict=True)`의 `_substitute_capacity`가 1·2·3차를 겹치지 않게 치를 만큼 글 문항이 있는지 확인합니다.

### 응시 상태 (`st.session_state.exam`, DB `sessions.progress`)
`domains, d, stage, i, items, answers, ms, deadline, entered, blurs, raw, mode, kind, self_done`
+ 위기 대처 `read_item`(읽기 단계 문항), `item_id`(보기를 열어 마감이 정해진 문항), `read_ms`(문항별 읽기 시간), 심층검사 `prior, seen, estimates`.
- 위기 대처 흐름: `reading()`이면 상황만 보여 주고(`start_reading`: 마감 없음) → '보기 열기'(`finish_reading`: 읽기 시간 기록, `start_item`으로 마감) → 판단.

### 자기평가
- 마지막 질문(`final_check.json`, `SelfItem.kind` = `desire` | `repeat`, `pair` = 짝 자기평가 문항)은 1차 끝에 한 번. 응답은 `domain = "fc"`, 점수는 `vd.final_scores`로 `sessions.self_scores`에 `_desire·_incons·_self_same`을 합쳐 저장. `exam["self_answers"]`에 시작 자기평가 응답을 남겨 짝 비교에 씁니다.
- `SelfItem(id, text, domain, reverse, check)`. 역문항은 `6 − 응답`.
- `exam.self_scores()` → 영역 평균(1~5) + `_checks`(점검 문항 4~5점 개수) + `_inflated`(2개 이상).
- 1차 세션의 `sessions.self_scores`와 `responses`(domain `"sr"`)에 저장. `seen_items`는 `"sr"`을 빼서 차수 출제에 영향이 없습니다.
- 결과 비교: `report.self_index(mean) = 100 + 15 × (mean − 3.6) / 0.55` (가정 분포 `SELF_NORM`).

## 4. 채점 ([07. 채점 원리](07_채점_원리.md))

3PL(최선·최악은 부분 점수) + EAP(θ 격자 −4~4, 161점) → EQ = 100 + 15z. 규준: 실제 첫 응시 300명 이상 → 시뮬레이션 규준(단계별) → 가정 규준.

## 5. 문항 추가하기

`scripts/items_<영역>.py`에 `Q(slot, prompt, choices, answer, explanation, rationale, styles)`를 추가하고 실행합니다.
같은 슬롯 안에서 a, b, c… ID가 자동으로 붙습니다. `styles`는 보기마다 유형 코드(`schema.STYLES`)를 공백으로 구분해 적습니다
(예 `"empath solve respect honest"`, 정답 위치와 무관하게 보기 순서대로). 해석 영역(인식·이해·맥락)은 정답 보기가 `acc`여야 합니다.

규칙:
- **네 보기 모두 괜찮은 방법**이고, 상황 속 **단서 하나**가 정답을 가른다. 오답은 "조금 다른 상황이었다면 정답"인 보기로 쓴다.
- 단서는 영역별 규칙을 따른다 (예: 대인관계 — 털어놓기만 원함→공감, 방법을 물음→해결, 혼자 있고 싶음→존중, 솔직한 의견을 구함→솔직; [09](09_유형_판정.md)).
- `lint_items`가 오답 속 뻔한 말('무시', '화를 내' 등)과 정답만 유난히 긴 보기를 경고합니다 (`validate_items.py`에 '주의'로 표시).
- 어려운 단계의 중간 보기 둘은 "일부만 맞음"이 되게 해 최선·최악이 하나씩만 분명하게.
- 같은 영역에서 같은 상황(prompt)이나 같은 정답 문구를 두 번 쓰지 않는다 (검증 스크립트가 막음).
- `rationale`에 근거 이론을 적는다 (검토·관리자 화면에 표시).

## 6. 커스텀 컴포넌트 규칙

- `data.token`이 같으면 DOM을 다시 만들지 않는다 (재실행 중 선택 상태 유지).
- `document`에 붙는 키보드·visibilitychange 리스너는 인스턴스당 하나, 화면에서 사라지면(`!isConnected`) 스스로 떼어 낸다.
- 최선·최악 컴포넌트는 같은 보기를 최선·최악으로 동시에 고를 수 없게 막는다.

## 8. 알아 둘 것

- 결과 화면: 영역 응답이 4개 이하면 영역 막대 대신 강점·키울 영역 후보 표(`COMPACT_MAX_ITEMS`), 종합 점수가 수준 경계에서 0.674 SE 안쪽이면 경계 근처 안내(`scoring.near_boundary`), 유형 이름 확신도(`Profile.confidence`).
- 실제 규준 전환 기준 `scoring.MIN_NORM_N = 300`, 시뮬레이션 규준의 영역 상관 `build_sim_norms.py --rho 0.5`.

- 커밋 메시지는 한국어 `<타입>: 무엇을`.
- Windows에서 Python `write_text`로 파일을 쓰면 줄바꿈이 CRLF가 되므로, 스크립트로 소스를 고친 뒤에는 LF로 맞춥니다.
- 시뮬레이션 규준은 문항 난이도 가정 위의 분포입니다. 문항·구성·보정값을 바꾸면 다시 만듭니다.
